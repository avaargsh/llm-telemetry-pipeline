# M11.2b: bounded OTLP JSON projection

Refs #56. Reference: OTLP Specification 1.11.1, https://opentelemetry.io/docs/specs/otlp/ (JSON encoding and trace request envelope). The implementation deliberately supports a restricted prefiltered GenAI JSON subset rather than a compliant general OTLP server.

DecodeOTLPJSON accepts an already-buffered UTF-8 body up to 256 KiB, traverses resourceSpans/scopeSpans/spans in order, and returns 1–256 typed spans or no result on error. Raw attributes per span limited to 64. Hex IDs canonicalized to lower case; status integer 0–2; six M10 scalar attributes mapped, int64 decimal strings or integer literals parsed without float64 conversion. Unknown attributes and resource/scope metadata discarded. Request and attempt correlation IDs not mapped. No wire tenant identity is trusted; the real authenticated scope must be provided separately to SubmitBatch. The fixed validation placeholder is not a tenant authorization decision. No queue mutation during decode.

This is not full Protobuf JSON mapping: no binary protobuf, gzip, gRPC, arbitrary AnyValue projection, empty requests or mixed non-GenAI traces; integer exponent forms are not supported. A bounded token preflight rejects duplicate decoded object keys everywhere (including escaped equivalents and ignored metadata), case-fold aliases of projected fields at their respective object paths, and nesting deeper than 64 containers. Unknown fields otherwise remain ignored. Numeric tokens are not converted to float64 in preflight. Body bound is on the passed buffer, not a streaming HTTP limit. No HTTP handler, response/ACK, auth, concurrency limiter, persistence, ledger writer or collector compatibility claim. Before mounting an endpoint, enforce streaming size limits and admission concurrency, define permanent versus retryable errors, and test actual collector traffic and PostgreSQL invariance.

Local isolated Go 1.23.2: RED undefined DecodeOTLPJSON API; GREEN three focused tests, race/vet/build in isolated package. Full hosted CI using pinned repository compiler required. Tests verify exact integer >2^53, zero, hex canonicalization, spoofed tenant and prompt exclusion, all-or-nothing invalid input, malformed JSON, byte and span limits.

Hardening regression: local isolated Go 1.23.2 using byte-identical original decoder and normalizer with the same batch-size constant: RED all ten ambiguity cases plus excessive nesting accepted; GREEN both new tests (ten subcases), race/vet/build. Unknown metadata remains accepted when unambiguous. This is focused decoder evidence, not a full repository or live collector run.
