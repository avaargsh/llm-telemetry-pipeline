# M11.2c: opt-in OTLP HTTP JSON admission

Refs #56. Reference: OTLP Specification 1.11.1 (https://opentelemetry.io/docs/specs/otlp/), HTTP trace path, success/failure messages and retryable status codes.

NewOTLPHTTPHandler constructs an independent net/http Handler for POST /v1/traces, restricted to the existing prefiltered GenAI JSON subset. No existing service mounts this handler. Credentials bind a distinct opaque bearer secret (32–512 visible ASCII bytes excluding comma; provision high entropy secrets externally) to one validated tenant. Configuration requires 1–128 credentials and 1–64 concurrent admitted requests per handler. Only SHA-256 digests and tenant scope are retained. Authentication checks all configured digests with constant-time comparisons. Tenant metadata on the wire cannot select the scope. No authoritative usage recorder or ledger writer is reachable from this handler.

Admission requires one JSON content type (optionally UTF-8 charset), identity encoding, at most 256 KiB read through MaxBytesReader, and a nonblocking concurrency slot held across body reading, decoding, queue admission and response. Existing decoder limits apply. HTTP 200 with empty JSON response means the entire batch was admitted to a volatile queue, not persisted or delivered. 401 authentication failure, 404/405 route/method, 415 unsupported media/encoding, 400 invalid request, 413 permanent size/batch limit. 503 on transient capacity/concurrency saturation with Retry-After: 1. Cancellation checked before admission; disconnect/cancellation racing admission or response can still result in duplicates. No partial admission, no deduplication, and process exit can lose all queued observations.

This is a restricted JSON handler, not full OTLP compliance, a live listener, binary protobuf/gzip/gRPC support or a durable ACK. Deployment must configure TLS, read/write/header/idle timeouts, header and connection limits, secret provisioning/rotation, and a queue consumer; global connection admission and per-tenant fairness are not provided. Do not mount until deployment and integration evidence is complete. Actual collector traffic and HTTP-to-real-PostgreSQL invariance remain acceptance work.

Isolated Go 1.23.2 RED missing API; GREEN three focused HTTP test groups including eleven request cases, config validation and blocked-reader concurrency; isolated package race/vet/build pass. Production dependency blobs verified against master; exact pushed source/test blobs checked. Hosted full repository CI required.

Integration gate: real PostgreSQL row snapshots plus a loopback TLS httptest server using the actual Handler exercise missing/unknown credentials, malformed duplicate fields, oversized body, two independent credential scopes, saturation with Retry-After, drain and successful retry, exact int64 token precision, and unchanged authoritative duplicate semantics. This test is not a production listener or collector; exact-head hosted execution is required before claiming success.
